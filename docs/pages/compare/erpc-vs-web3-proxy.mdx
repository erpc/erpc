# eRPC vs web3-proxy

[web3-proxy](https://github.com/llamanodes/web3-proxy) is the Rust proxy that ran LlamaNodes' public RPC.
It ships a full RPC-as-a-service layer: wallet login, keys, tiers and compute-unit billing.
eRPC is an EVM and Solana JSON-RPC proxy built around failover, a finality-aware cache, and cost control.
Every cell below links to the page or line that states it. Facts were checked on 2026-10-22.

"Not found in source" means a search of the web3-proxy source found no code for it.

## Where web3-proxy is stronger

- **RPC-as-a-service built in.** Users, sub-users, tiers, compute-unit pricing, on-chain deposits and Stripe ([compute_units.rs](https://github.com/llamanodes/web3-proxy/blob/f4a71ee0b621c461828956436f6d55372228ec18/web3_proxy/src/compute_units.rs#L14-L80)). eRPC has no billing.
- **Private transaction routing.** `eth_sendRawTransaction` goes to `private_rpcs` such as Flashbots ([app/mod.rs](https://github.com/llamanodes/web3-proxy/blob/f4a71ee0b621c461828956436f6d55372228ec18/web3_proxy/src/app/mod.rs#L1101-L1185)).
- **ERC-4337 bundler routing** to a separate upstream pool ([app/mod.rs](https://github.com/llamanodes/web3-proxy/blob/f4a71ee0b621c461828956436f6d55372228ec18/web3_proxy/src/app/mod.rs#L1468-L1477)).
- **Automatic archive-depth probing** per upstream, with no config ([one.rs](https://github.com/llamanodes/web3-proxy/blob/f4a71ee0b621c461828956436f6d55372228ec18/web3_proxy/src/rpcs/one.rs#L368-L450)).

## Where eRPC is stronger

- Active releases; web3-proxy has had no commit since December 2023.
- Hedging, circuit breaker and response consensus ([failsafe](/config/failsafe)).
- Shared, finality-aware cache on Redis, PostgreSQL or DynamoDB ([cache](/config/database/evm-json-rpc-cache)).
- `eth_getLogs` range splitting instead of a range cap ([getLogs splitting](/reference/evm/getlogs-splitting)).
- Many chains, EVM and Solana, in one process ([networks](/config/projects/networks)).

### Moving from web3-proxy to eRPC

| web3-proxy concept | eRPC equivalent |
|---|---|
| one process per `chain_id` | one process, many `networks[]` ([networks](/config/projects/networks)) |
| `balanced_rpcs` | `projects[].upstreams[]` ([upstreams](/config/projects/upstreams)) |
| `backup = true` upstream | fallback tier in a selection policy ([selection policies](/config/projects/selection-policies)) |
| `soft_limit` / `hard_limit` | upstream rate-limit budget ([rate limiters](/config/rate-limiters)) |
| RPC keys in the URL | `secret` or `database` auth ([auth](/config/auth)) |
| in-memory response cache | `database.evmJsonRpcCache` ([cache](/config/database/evm-json-rpc-cache)) |

### Keep web3-proxy when

- You need its built-in billing and user accounts and accept an unmaintained codebase.
