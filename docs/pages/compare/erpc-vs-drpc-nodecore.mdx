# eRPC vs dRPC NodeCore

[NodeCore](https://github.com/drpcorg/nodecore) is dRPC's open-source RPC stack in Go.
It covers 15+ chain families over JSON-RPC, REST and gRPC, and links to dRPC's hosted network.
eRPC is an EVM and Solana JSON-RPC proxy built around failover, a finality-aware cache, and cost control.
Every cell below links to the page or line that states it. Facts were checked on 2026-10-22.

"Not documented" means the NodeCore docs do not describe it and a search of its source found no code for it.
The [dRPC NodeCore page](https://drpc.org/docs/nodecore-open-source-rpc-stack) also lists a circuit breaker and OpenTelemetry traces. The open-source repo at the commit above does not document them, so the table does not count them.

## Where NodeCore is stronger

- **Chain coverage.** 15+ chain families, with REST, Tendermint and gRPC upstreams ([README](https://github.com/drpcorg/nodecore/blob/8d8d79af258b5f7897ec77709eb495c29e744973/README.md#L16)). eRPC serves EVM and Solana only.
- **Subscriptions beyond EVM.** Solana and other chain families, and EVM streams built from all upstreams together ([subscriptions](https://github.com/drpcorg/nodecore/blob/8d8d79af258b5f7897ec77709eb495c29e744973/docs/nodecore/13-subscriptions.md#L1-L30)). eRPC serves only EVM `eth_subscribe`.
- **Signed-response quorum** with dRPC providers ([quorum](https://github.com/drpcorg/nodecore/blob/8d8d79af258b5f7897ec77709eb495c29e744973/docs/nodecore/10-quorum.md#L32-L38)).
- **Contract allowlists per API key** for `eth_call` and `eth_getLogs` ([auth](https://github.com/drpcorg/nodecore/blob/8d8d79af258b5f7897ec77709eb495c29e744973/docs/nodecore/03-auth.md#L172-L207)).
- **Official Helm chart** ([chart](https://github.com/drpcorg/nodecore/blob/8d8d79af258b5f7897ec77709eb495c29e744973/chart/nodecore/README.md#L10)). eRPC ships raw manifests ([kubernetes](/deployment/kubernetes)).

## Where eRPC is stronger

- Consensus across any upstreams, not only signed ones ([consensus](/config/failsafe/consensus)).
- Circuit breaker and OpenTelemetry tracing in the open-source code ([circuit breaker](/config/failsafe/circuit-breaker), [tracing](/operation/tracing)).
- `eth_getLogs` range splitting ([getLogs splitting](/reference/evm/getlogs-splitting)).
- Rate limits on clients, projects and networks, not only upstreams ([rate limiters](/config/rate-limiters)).
- DynamoDB cache driver and finality-aware cache buckets ([cache](/config/database/evm-json-rpc-cache)).
- Config in TypeScript, with typed selection policies ([selection policies](/config/projects/selection-policies)).

### Moving from NodeCore to eRPC

| NodeCore concept | eRPC equivalent |
|---|---|
| `upstream-config.upstreams[]` | `projects[].upstreams[]` ([upstreams](/config/projects/upstreams)) |
| `chain: ethereum` | `networks[].evm.chainId: 1` ([networks](/config/projects/networks)) |
| `failsafe-config.retry` / `hedge` | `failsafe[].retry` / `failsafe[].hedge` ([retry](/config/failsafe/retry), [hedge](/config/failsafe/hedge)) |
| TypeScript scoring function | selection policy ([selection policies](/config/projects/selection-policies)) |
| cache policies | `database.evmJsonRpcCache.policies` ([cache](/config/database/evm-json-rpc-cache)) |

### Keep NodeCore when

- You serve non-EVM, non-Solana chains.
- You route to dRPC providers and want their signed-response quorum.
