# eRPC vs dshackle

[dshackle](https://github.com/emeraldpay/dshackle) and eRPC both put one endpoint in front of many blockchain nodes.
dshackle comes from wallet infrastructure: a gRPC API with streams, signed responses, and deep Bitcoin support.
eRPC is an EVM and Solana JSON-RPC proxy built around failover, a finality-aware cache, and cost control.
Every cell below links to the page or line that states it. Facts were checked on 2026-10-22.

## Where dshackle is stronger

- **gRPC API with streams.** Head, balance (ETH, ERC-20, BTC with xpub) and tx-status subscriptions ([methods](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/docs/07-methods.adoc#L11-L30)).
- **Signed responses.** A client can prove which upstream produced an answer ([methods](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/docs/07-methods.adoc#L94-L117)).
- **Bitcoin.** bitcoind, Esplora and ZeroMQ notifications ([reference](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/docs/reference-configuration.adoc#L944-L992)). eRPC does not serve Bitcoin.
- **Instance mesh.** dshackle instances link over mTLS gRPC across regions ([architecture](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/docs/01-architecture-intro.adoc#L63-L72)).
- **Fork-aware routing.** Upstreams on the losing fork still serve data below the fork point ([upstream config](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/docs/04-upstream-config.adoc#L119-L150)).

## Where eRPC is stronger

- Hedging, circuit breaker and consensus as separate failsafe steps ([failsafe](/config/failsafe)).
- Finality-aware cache on four storage drivers ([cache](/config/database/evm-json-rpc-cache)).
- `eth_getLogs` range splitting ([getLogs splitting](/reference/evm/getlogs-splitting)).
- Client auth and rate limits for public or multi-team endpoints ([auth](/config/auth), [rate limiters](/config/rate-limiters)).
- Solana support ([networks](/config/projects/networks)).

## Note on dshackle versions

The latest dshackle release, v0.17.0, is Kotlin. Since April 2026 the `master` branch is a Rust rewrite, version `0.18.0-dev` ([Cargo.toml](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/Cargo.toml#L1-L4)).
The dshackle README says `master` "should not be used in production" ([README](https://github.com/emeraldpay/dshackle/blob/896ab53b7c8806b5ee481a14aa1e1c04e7bc1a78/README.adoc#L308)).
dRPC keeps a separate Kotlin fork, [drpcorg/dshackle](https://github.com/drpcorg/dshackle), with more chains and JWT auth. This page compares `emeraldpay/dshackle`.

### Moving from dshackle to eRPC

| dshackle concept | eRPC equivalent |
|---|---|
| `cluster.upstreams[]` | `projects[].upstreams[]` ([upstreams](/config/projects/upstreams)) |
| `blockchain` per upstream | `networks[].evm.chainId` ([networks](/config/projects/networks)) |
| `role: primary/secondary/fallback` | selection policy ([selection policies](/config/projects/selection-policies)) |
| `methods.enabled[].quorum` | `failsafe[].consensus` ([consensus](/config/failsafe/consensus)) |
| `methods.enabled` / `methods.disabled` | `allowMethods` / `ignoreMethods` ([upstreams](/config/projects/upstreams)) |
| Redis cache | `database.evmJsonRpcCache` with a Redis connector ([cache](/config/database/evm-json-rpc-cache)) |

### Keep dshackle when

- Clients use its gRPC streams or signed responses.
- You serve Bitcoin.
