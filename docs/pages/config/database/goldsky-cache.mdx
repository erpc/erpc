# Goldsky cache (gRPC)

Goldsky hosts a read-only gRPC cache backed by its indexed chain data. Add it as a `grpc` [cache connector](/config/database/drivers) and eRPC asks it first for historical reads; a miss goes to your upstreams exactly as before.

## Set it up

<Steps>

### Get a Goldsky API key

Sign up or sign in at [app.goldsky.com](https://app.goldsky.com), open **Edge RPC**, click **New endpoint**, then **Create endpoint**. Copy the **API Key** shown in the **Edge Endpoint Created** dialog. The same key works for Edge RPC and for the cache. Keep it out of your config file:

```bash
export GOLDSKY_API_KEY=gs_edge_...
```

### Add the connector and a policy

One URL per chain; eRPC calls `ChainId` on each at startup to map it to its network.

<ConfigTabs
  path="database.evmJsonRpcCache"
  yaml={`database:
  evmJsonRpcCache:
    connectors:
      - id: goldsky-cache
        driver: grpc
        grpc:
          servers:
            - grpcs://edge.goldsky.com/cache/ethereum
            - grpcs://edge.goldsky.com/cache/base
          headers:
            x-api-key: \${GOLDSKY_API_KEY}
          # a read the cache can't answer this fast goes to your upstreams;
          # raise it to keep wide eth_getLogs ranges in the cache
          getTimeout: 200ms
      - id: memory-cache
        driver: memory
    policies:
      - connector: goldsky-cache
        network: "evm:1|evm:8453"
        method: "eth_getBlockByNumber|eth_getBlockByHash|eth_getLogs|eth_getTransactionByHash|eth_getTransactionReceipt|eth_getBlockReceipts|eth_chainId"
        finality: finalized
      - connector: goldsky-cache
        network: "evm:1|evm:8453"
        method: eth_blockNumber
        finality: realtime
      - connector: memory-cache
        network: "*"
        method: "*"
        finality: finalized`}
  ts={`database: {

    connectors: [
      {
        id: "goldsky-cache",
        driver: "grpc",
        grpc: {

            "grpcs://edge.goldsky.com/cache/base",
          ],
          headers: { "x-api-key": "\${GOLDSKY_API_KEY}" },
          // a read the cache can't answer this fast goes to your upstreams;
          // raise it to keep wide eth_getLogs ranges in the cache
          getTimeout: "200ms",
        },

The Goldsky cache is read-only. Keep a memory or Redis connector (above: `memory-cache`) for writes and for recent blocks the cache has not indexed yet.

### Check it works

At startup eRPC logs one line per URL:

```
gRPC client initialized for network  server=grpcs://edge.goldsky.com/cache/ethereum networkId=evm:1
```

Then request an old block and look at the `X-ERPC-Cache` response header — `HIT` when the response came from a cache, `MISS` when it went to an upstream:

```bash
curl -si http://localhost:4000/main/evm/1 \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getBlockByNumber","params":["0x1000000",false]}' \
  | grep -i x-erpc-cache
```

Per connector, the Prometheus counter `erpc_cache_get_success_hit_total{connector="goldsky-cache"}` counts hits.

</Steps>

## What it serves

- **Methods:** `eth_getBlockByNumber`, `eth_getBlockByHash`, `eth_getLogs`, `eth_getTransactionByHash`, `eth_getTransactionReceipt`, `eth_getBlockReceipts`, `eth_chainId`, `eth_blockNumber`. eRPC never sends other methods to the connector.
- **Misses:** data not indexed yet (e.g. the chain tip) answers gRPC `OUT_OF_RANGE`; eRPC treats it as a cache miss and calls your upstreams.
- **`eth_getLogs`:** up to 30,000 blocks per call. Block, transaction and receipt reads answer well within `getTimeout: 200ms`; a wide or dense `eth_getLogs` range takes longer and goes to your upstreams unless you raise it.
- **Chains:** abstract, arbitrum, arbitrum-sepolia, arc, avalanche, base, base-sepolia, bsc, celo, ethereum, gnosis, hyperevm, ink, monad, optimism, polygon, robinhood, robinhood-testnet, sei, sepolia, tempo, tron. Use the name in the URL: `grpcs://edge.goldsky.com/cache/<chain>`.
- **No writes:** the connector is read-only and eRPC never writes to it, so the policy needs no `appliesTo`.

## Monad `eth_query*` (MIP-16)

On Monad (chain 143), the same endpoint also serves `eth_queryLogs` and `eth_queryTransactions` ([MIP-16](https://github.com/monad-crypto/MIPs/pull/89)) natively through `bds.evm.QueryService`: one paged read from Goldsky's index instead of a node call per block. Add it as a gRPC **upstream** (not a cache connector) that allows those methods. eRPC tries it first and answers `eth_queryBlocks`, `eth_queryTraces` and `eth_queryTransfers` with the [query shim](/reference/evm/method-handlers) on your archive node:

<ConfigTabs
  path="upstreams"
  yaml={`upstreams:
  - id: goldsky-monad
    endpoint: grpcs://edge.goldsky.com/cache/monad
    grpc:
      headers:
        x-api-key: \${GOLDSKY_API_KEY}
    evm:
      chainId: 143
    ignoreMethods: ["*"]
    allowMethods:
      - eth_chainId
      - eth_getBlockByNumber
      - eth_queryLogs
      - eth_queryTransactions
  - id: monad-archive
    endpoint: https://your-monad-archive-node
    evm:
      chainId: 143
      # serves eth_queryBlocks, eth_queryTraces and eth_queryTransfers,
      # and any range the Goldsky upstream cannot answer
      queryShim:
        enabled: true`}
  ts={`upstreams: [
  {
    id: "goldsky-monad",
    endpoint: "grpcs://edge.goldsky.com/cache/monad",
    grpc: { headers: { "x-api-key": "\${GOLDSKY_API_KEY}" } },
    evm: { chainId: 143 },
    ignoreMethods: ["*"],
    allowMethods: ["eth_chainId", "eth_getBlockByNumber", "eth_queryLogs", "eth_queryTransactions"],
  },
  {
    id: "monad-archive",
    endpoint: "https://your-monad-archive-node",
    evm: {
      chainId: 143,
      // serves eth_queryBlocks, eth_queryTraces and eth_queryTransfers,
      // and any range the Goldsky upstream cannot answer
      queryShim: { enabled: true },
    },
  },
]`}
/>

- **Both transports:** JSON-RPC `eth_query*` and gRPC `QueryService` streams use the same upstreams and return the same MIP-16 pages.
- **Range:** genesis to the chain tip. eRPC resolves `latest`, `safe` and `finalized` to block numbers before it calls the upstream.
- **Without an archive node:** leave out `monad-archive`. `eth_queryBlocks`, `eth_queryTraces` and `eth_queryTransfers` then return `-32004` (method not supported).
- **Edge RPC:** Goldsky Edge RPC endpoints for Monad (`https://edge.goldsky.com/standard/evm/143`) already serve all five `eth_query*` methods this way.
