# WebSocket

Clients can open a WebSocket on the same URL they already use for HTTP
(`ws://host:4000/<project>/evm/<chainId>`) to subscribe to `newHeads` and
`logs`. Events come from the network's [head cache](/config/database/head-cache).
Subscribers on one replica share its head tracking and hydration. Replicas verify
their heads independently and can reuse immutable block/log payloads from Redis,
so fleet-wide provider traffic may be duplicated. Reorgs arrive as `removed: true`
logs. Ordinary JSON-RPC calls stay on HTTP.

Disabled by default.

## Quick taste

```yaml
server:
  webSocket:
    enabled: true
database:
  evmJsonRpcCache:
    connectors:
      - id: redis-cache
        driver: redis
        redis:
          uri: redis://redis:6379
projects:
  - id: main
    networks:
      - architecture: evm
        evm:
          chainId: 1
          # the upgrade requires the Redis head cache on this network
          headCache:
            enabled: true
            connectorId: redis-cache
```

## Config schema (`server.webSocket`)

Defaults from `WebSocketServerConfig.SetDefaults` (<SourceLink file="common/config_headcache.go" lines="138-160" />), called from <SourceLink file="common/defaults.go" lines="793" />.

| Field | Default | Meaning |
|---|---|---|
| `enabled` | `false` | When false, Upgrade requests are handled as plain HTTP (no 101). |
| `maxConnections` | `1024` | Concurrent WS connections per process. Beyond it the upgrade gets HTTP 503. |
| `maxConnectionsPerProject` | `0` (off) | Concurrent WS connections per project (0..`maxConnections`). Beyond it the upgrade gets HTTP 503, and other projects are unaffected. |
| `maxSubscriptionsPerConnection` | `32` | Further `eth_subscribe` calls return JSON-RPC error `-32005`. |
| `sendQueueSize` | `256` | Outbound messages queued per connection, and the head cache event queue per subscription. Notifications wait up to `writeTimeout` for space, so a large block reaches a client that keeps reading. A client stalled longer, or a head cache queue overflow, closes with 1008. |
| `maxMessageBytes` | `1MB` (min 1024) | Inbound frame limit. Larger frames close with 1009. |
| `writeTimeout` | `10s` | Per outbound frame. A timeout closes with 1008. |
| `pingInterval` | `30s` | Keepalive ping and credential re-check period. `0` (unset) uses the `30s` default and a negative value fails config validation, so pings cannot be disabled. |

## Behavior

- **Contract.** Only `eth_subscribe` and `eth_unsubscribe` are accepted. Any other method gets `-32601` (use HTTP). A batch (top-level JSON array) gets a single `-32600`. Unparsable JSON gets `-32700`, and valid JSON that is not a request object gets `-32600`. Frames are handled sequentially per connection.
- **Head cache required.** The upgrade gets HTTP 503 unless the network has an enabled head cache (`evm.headCache` with a Redis `connectorId`). Notifications come from the replica's locally verified canonical events. eRPC never proxies upstream WebSockets.
- **Routing.** Same path and domain aliasing as HTTP. A connection is bound to one project and network.
- **Auth.** Credentials (`?secret=`, `X-ERPC-Secret-Token`, `Authorization`) are taken from the upgrade request. They are checked at upgrade (401 on failure) and again for every message through the project's consumer auth. `ignoreMethods`/`allowMethods` apply.
- **Origin.** Browsers do not apply CORS to WebSockets. When the project has `cors.allowedOrigins`, an upgrade with a non-matching `Origin` gets 403.
- **Subscriptions.** `newHeads` emits header fields (no `transactions`, `uncles`, `size`, `totalDifficulty`, `withdrawals`) per new canonical block, ascending. `logs` accepts `address` (string or array) and `topics` (up to 4 positions, `null` wildcard, nested arrays for OR). On a reorg, orphaned matching logs are sent first with `removed: true` (highest block first), then the new canonical logs. The subscription id reply always precedes its notifications. Setup consumes project rate-limit budget for `eth_subscribe`.
- **Tip.** Each replica verifies its own head, so `newHeads` may briefly differ from HTTP `latest` or another replica's notifications when upstream views lag.
- **Unsubscribe.** `eth_unsubscribe` returns `false` for ids that were not created on the same connection.

## Edge cases & gotchas

1. **No silent gaps.** Every head-cache event is checked for continuity. If a missing height cannot be backfilled from the locally verified window, or if a subscription queue overflows, the connection closes with 1008 rather than silently skipping notifications. Clients should reconnect, resubscribe and recover missed logs with `eth_getLogs` over HTTP.
2. **Id-less requests.** A JSON-RPC 2.0 `eth_subscribe` or `eth_unsubscribe` without an `id` is treated as a notification: it gets no reply and does not create or remove a subscription (`TestWs_IdlessNotificationsHaveNoSubscriptionEffects`).
3. **Stale head cache.** When this replica's head cache stops serving (see its `maxStaleness`), no events are produced.
4. **Shutdown.** Connections are hijacked, so `http.Server.Shutdown` does not wait for them. They close with 1001 when the application context ends. New upgrades during draining get 503.
5. `maxConnections` and `maxConnectionsPerProject` are per process, not per client IP or fleet. Front eRPC with a per-client connection limit at the load balancer.
6. Only `newHeads` and `logs` are supported. `newPendingTransactions`, `syncing` and unknown kinds return `-32601`.
7. **Keepalive and re-auth.** Every `pingInterval` the server pings (a missing pong within `writeTimeout` closes with 1008) and re-checks the upgrade credentials through consumer auth, consuming one auth rate-limit permit when the strategy has a `rateLimitBudget`. A revoked key or expired JWT stops streaming within about one `pingInterval`, closing with 1008 `unauthorized`.
8. **Server timeouts.** Upgraded connections are hijacked, so they outlive `server.writeTimeout` (`TestWs_OutlivesHTTPWriteTimeout`).
9. **Fork compatibility.** Configs written for the unmerged fork branch must drop `server.webSocket.maxInflightPerConnection` and `maxBatchSize`. Those keys no longer exist.
